# 三级幻觉治理机制 (Hallucination Governance)

> **核心原则：** 事前预防 → 事中监督 → 事后管控

## 📊 业界标准

根据2025-2026年AI Agent最佳实践，幻觉治理必须包含三个层级：

### 事前预防（Prevention）
- 输入校验和约束
- 知识源可信度评估
- 提示词工程规范
- 事实核查清单

### 事中监督（Detection）
- 置信度阈值监控
- 关键节点人工复核
- 多Agent交叉验证
- 实时异常检测

### 事后管控（Mitigation）
- 幻觉案例归档
- 根因分析
- 模型/流程迭代改进

---

## 🛡️ 实施规则

### 1. 事前预防

#### 1.1 知识源白名单

当Agent需要引用事实或数据时，**必须**使用以下可信来源：

```
✅ 可信来源：
- 项目文档（docs/）
- 代码注释
- 官方API文档
- 团队共享记忆（SHARED_MEMORY.md）
- 经验证的个人记忆（MEMORY.md）

❌ 不可信来源：
- Agent"记得"的未验证信息
- 用户未提供的数据
- 推测或假设
```

#### 1.2 提示词约束

在创建任务或Agent时，**必须**包含以下约束：

```markdown
【事实核查要求】
1. 所有技术声明必须引用具体来源
2. 不确定的信息必须明确标注"推测"
3. 代码示例必须经过验证
4. API调用必须引用官方文档
```

#### 1.3 置信度声明

Agent在回答时**必须**声明置信度：

```
高置信度（90-100%）：基于官方文档或已验证代码
中置信度（70-89%）：基于团队实践或经验
低置信度（<70%）：基于推测或未验证信息 → 需要人工验证
```

### 2. 事中监督

#### 2.1 自动检测规则

以下情况**自动触发**幻觉检测：

- Agent做出没有引用的技术声明
- 代码包含未经验证的API调用
- 回答包含"我认为"、"可能"、"大概"等不确定词汇
- 置信度 < 70%

#### 2.2 交叉验证

关键声明需要**至少2个独立Agent**验证：

```
Agent A 声明 → Agent B 验证 → Agent C 复核 → 共识确认
```

#### 2.3 人工复核点

以下情况**必须**人工复核：

- 涉及安全相关的声明
- 架构决策
- 生产部署
- 数据迁移

### 3. 事后管控

#### 3.1 案例归档

发现幻觉后**立即**归档：

```json
{
  "id": "hallucination-001",
  "timestamp": "2025-01-15T10:30:00Z",
  "agentId": "developer",
  "claim": "声称某个API存在",
  "reality": "实际该API不存在",
  "severity": "high",
  "rootCause": "模型训练数据过期",
  "lesson": "必须引用官方文档验证API存在性"
}
```

#### 3.2 根因分析

对每个幻觉案例进行根因分析：

```
1. 为什么Agent会产生幻觉？
   - 模型训练数据问题
   - 提示词不够明确
   - 知识源不足
   - 推理错误

2. 如何预防类似幻觉？
   - 更新知识源
   - 改进提示词
   - 添加验证步骤
   - 调整模型参数
```

#### 3.3 持续改进

每月分析幻觉趋势，改进：

- 提示词模板
- 知识源质量
- 验证流程
- 模型选择

## 📝 实施检查清单

### 任务创建时
- [ ] 包含事实核查要求
- [ ] 指定可信知识源
- [ ] 定义置信度阈值
- [ ] 设置人工复核点

### Agent执行时
- [ ] 引用所有技术声明
- [ ] 声明置信度
- [ ] 对不确定信息进行交叉验证
- [ ] 在置信度低时请求人工帮助

### 任务完成后
- [ ] 验证所有关键声明
- [ ] 记录可疑输出
- [ ] 归档发现的幻觉
- [ ] 更新经验教训

---

## 🎯 质量指标

### 领先指标（Leading Indicators）
- 低置信度回答比例（目标：< 10%）
- 引用缺失率（目标：< 5%）
- 交叉验证触发率（目标：> 90%）

### 滞后指标（Lagging Indicators）
- 幻觉发现数量（趋势下降）
- 幻觉严重程度分布
- 用户报告的幻觉数量

## 🔧 工具支持

### 自动检测工具
```bash
# 检查代码中是否有未验证的API调用
node scripts/detect-hallucinations.mjs --type code

# 检查文档中是否有未引用的声明
node scripts/detect-hallucinations.mjs --type docs

# 分析Agent输出的置信度
node scripts/detect-hallucinations.mjs --type output
```

### 手动验证清单
```bash
# 运行完整的幻觉检测
node scripts/hallucination-check.mjs --full

# 仅检查特定任务
node scripts/hallucination-check.mjs --task TASK_ID
```

## ⚠️ 禁止行为

❌ **绝对禁止：**
1. 在没有引用的情况下做出技术声明
2. 隐瞒不确定的信息
3. 忽略置信度声明
4. 跳过交叉验证步骤
5. 不归档发现的幻觉

## ✅ 最佳实践示例

### ✅ 正确的回答

```
根据官方文档（https://api.example.com/docs），该API的参数如下：
- `userId`: string (required)
- `options`: object (optional)

置信度：95%（基于官方文档）

注意：文档版本为2.1，请确认你使用的是兼容版本。
```

### ❌ 错误的回答（幻觉）

```
我认为该API可能需要userId和token参数。
（没有引用来源，没有置信度，使用"我认为"、"可能"）
```
